Base profile vector and query vector both feed the nudge step; only the query and the nudge itself run per search — everything else was already sitting in memory.

Why this isn't just "average the two vectors"

Our current model was trained to read profile and query together, so its vector space has no reason to behave predictably under simple addition. Making the nudge work well means training a small extra piece — a few-layer network, f(base_vec, query_vec) → nudged_vec — whose whole job is to land close to what the full joint pass would have produced. That's a real addition to the model, not just a change to how we serve it.
