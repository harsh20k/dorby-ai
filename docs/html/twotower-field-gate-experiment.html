Does a Learned Gate Over Profile Pieces Beat Plain Query-Only?

query_weighted/ found a fixed blend (query + profile, weighted) beats plain concatenation. This experiment tried a smarter version: one shared tower, seeker side split into three pieces — the search query, lookingFor, positioning — each encoded separately and combined by a small learned gate instead of one fixed weight. It's the worst of four approaches on every retrieval metric (MRR, recall@1, recall@10) — decomposing the profile and learning to combine it did not recover what a single coherent query-only string already gets for free.

All 200 real pairs

Same population, same metrics as every other row in this project. The field-gate model beats the split-towers approach on classification (AUC, hard-neg AUC) but trails everything — including split towers — on retrieval.

How the gate combines pieces

A small trainable layer (9,219 parameters) looks at the three piece embeddings together and outputs one softmax weight per piece — a learned, per-seeker version of the fixed alpha blend used elsewhere in this project.

query embedding, lookingFor embedding, positioning embedding → Linear(3×1024 → 3) → softmax → weighted sum → one seeker vector
