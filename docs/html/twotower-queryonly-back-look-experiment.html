Where did the improvement actually come from?

Same exact text (seeker = query only, candidate = background+lookingFor) scored at three stages: frozen base voyage-4-nano with no fine-tuning at all, top1_ctrl's existing weights with this text swapped in (general fine-tuning transfer — it never saw this text during training), and this experiment's adapter, trained specifically on this text.

Recall@1 and recall@5 were mostly decided by the text choice, not training — frozen base nano already gets R@1 0.28 / R@5 0.76 for this combo; general and specific fine-tuning together move R@1 by only +0.02 and leave R@5 flat (even slightly down).

Hard-negative AUC is where training earns its keep. General fine-tuning transfer (stage 1→2) already buys +0.085 (0.437→0.522) just from having trained on something. Training specifically on this text (stage 2→3) adds another +0.134 (0.522→0.656) — the single largest move in the whole chain, and the reason this experiment sets a new project-wide record. Pair AUC and easy-neg AUC both dip slightly in that same last step — this is a real trade, not a free win on every axis.

A new project-wide hard-negative AUC record

Real negatives in this project are production's own false positives — plausible intros humans still declined — so hard-neg AUC is the metric closest to production reality.

Previous best of any model tested (embedding or LLM-judge): 0.6466 — gemini-3.1-flash-lite naive judge, one API call per candidate, outside the <100ms serving budget.

This fine-tune: 0.6564 — a merged LoRA adapter, no extra serving cost over frozen nano.

Not a clean sweep against every free lever

top1_ctrl + eval-time query-weighting is a zero-training text swap on the existing checkpoint — this arm doesn't beat it on everything.

query_only swap (frozen, no retrain): MRR 0.5076, R@1 0.32 — both ahead of this arm's 0.4791 / 0.30.
alpha_0.6 blend (frozen, no retrain): pair AUC 0.6129 — ahead of this arm's 0.5983.

This experiment's genuine edge is hard-negative resistance, plus proof that a frozen-model field/query search is a validated way to find a text representation worth actually training on.
