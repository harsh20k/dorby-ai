Does knowing what the candidate wants help predict the match?

A static reciprocal scoring rule — built from Ga Wu's "Dynamic Reciprocal User Matching with Fast Weight Programmers" proposal — tested against the real 200-pair accept/decline dataset. No training, one fitted number.

Directionally positive, not statistically proven
What the seeker wants vs. what the candidate offers — and the reverse. S = s_forward + λ·s_reciprocal

What was tested

The paper's real contribution — a Fast Weight Programmer memory that adapts a user's preference vector from a session's (impression, skip, like, message, …, timestamp) history — needs interaction logs this project's dataset does not have: every real pair is a single static (seeker, candidate, accept/decline) outcome, no session, no sequence. That mechanism wasn't built here; fabricating histories to exercise it would defeat the point of an offline eval.

What the paper's own math reduces to with zero history — q_t = Norm(k_u) — is exactly this dataset's shape. So this experiment implements that slice, plus the one piece nothing else in this project had tried: the static reciprocal term, scoring not just whether the seeker's stated want matches the candidate's background, but the reverse — whether the candidate's own want matches the seeker's background too.

s_forward(u, i)   = k_u · v_i  # what u wants vs. what i offers
s_reciprocal(i, u) = k_i · v_u  # what i wants vs. what u offers
S(u, i) = s_forward + λ · s_reciprocal  λ = 1.75, fit by grid search on 131 real train pairs only

Both k and v come from the same frozen voyage-4-nano — zero fine-tuning, one scalar fit. The paper leaves the two encoders "potentially different"; untying them is a further step, not this one.

But is the gain real?

A 5,000-resample bootstrap of the AUC delta (stratified by label) says: probably, not certainly. Both intervals cross zero.

Holdout
Δ AUC = +0.0388, 95% CI [−0.0655, 0.1474] · P(Δ>0) = 0.76
All-200
Δ AUC = +0.0326, 95% CI [−0.0333, 0.0994] · P(Δ>0) = 0.84

Same sign in three separate checks — train (where λ was fit), holdout, and all-200 — for zero training cost. That consistency is the reason to keep pulling this thread. It is not, on its own, proof the gain survives at this sample size.

What it does not beat: retrieval. MRR trails Voyage-4-large and top1_ctrl on both populations — expected, since retrieval here ranks by s_forward alone, using only the short lookingFor + query text rather than each baseline's full profile. The gain is a reranking effect, which is exactly where the paper places the reciprocal term (never in retrieval) — and it's cheap under this project's <100 ms serving budget, since it's one precomputed dot product per already-retrieved candidate.

What's next

  • Untie the encoders. This run uses one frozen model for both look-for and background views. The paper leaves them "potentially different" — two separately-trained LoRA adapters is the natural next step.
  • Tighten the confidence before trusting λ = 1.75 — a larger eval population or k-fold re-fitting over the 131 train pairs would narrow the bootstrap interval before this informs a real decision.
  • Try full calibration (w1·s_fwd + w2·s_recip + b) instead of one shared scalar — more flexible, same fit-on-train-only discipline.
