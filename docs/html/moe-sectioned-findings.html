The good idea, and the wrong reason

Splitting a networking request into its individual asks, and scoring each one separately, beats every model we have tried on this task. The clever part we designed to go with it — learning which ask matters — turns out to contribute nothing at all.

The honest reading

One prediction right, and it happened to be the one the whole thing rested on. The three sophisticated ideas layered on top of it were all wrong, and each was wrong in the direction of "the clever thing didn't beat the simple thing." That is worth more than a clean win: the simple version is cheaper to run, easier to explain, and now the one we would ship.

03 — what changedOne row per ask, instead of one row per pair

A person's networking request is not one thing. In our data the median seeker writes five separate asks — customers, hiring, fundraising, partnerships — and an introduction is usually accepted because it satisfies one of them.

Before this experiment, all of that reached the model as a single number: how many sections the person wrote. Everything else was averaged into one whole-profile similarity score. 131 training examples stayed 131 rows.

Now each ask becomes its own row — 131 pairs become 708 rows — and the model answers a narrower, more answerable question: does this person satisfy this specific request? The per-ask verdicts are then combined into one decision about the pair.

A real example

Alan runs a returns-logistics company and wrote four asks. Garrett, an operations executive, ranks 92nd percentile on Alan's "brand-side operators" ask and 70th on his "SaaS companies for partnerships" ask — correctly, since Garrett is a person, not a company. They connected. The old model averaged those four numbers together before ever looking at them.

04 — the missesThree defects found along the way

Each one would have produced a confident, wrong answer. All three were caught by a result looking strange rather than by anything failing.

The reduction layers were the model
Two layers whose job was to shrink the embeddings held roughly 960,000 parameters — fitted on 708 rows. The model had far more capacity to memorise than there was data to learn from.
tell: four runs, four different rankings of the same five arms
The GPU run loaded the model at double precision
An 8-billion-parameter model at full precision is ~32 GB of weights before a single calculation, on a 40 GB card. Our own existing code already loaded it correctly; this script was written fresh instead of copied.
tell: out of memory, 36.68 GiB allocated, 942 MiB free
Half the embeddings were computed the wrong way
Qwen3 treats a question and an answer differently and needs to be told which is which. We told it everything was an answer. Fixing it did not rescue the score — which is itself the finding.
tell: found by reading our own model registry, not by any error

05 — corroborationThe Qwen3 result stopped being surprising

When Qwen3-8B embeddings lost to plain keyword matching here, it looked like an anomaly — that model was believed to beat the production system outright.

That belief was retracted a day later, for unrelated reasons. Re-scored on all 200 real pairs instead of a 69-pair slice, Qwen3 loses to the production model on every measure, with a below-chance score on the hardest cases. So this experiment and that one now agree, from completely different directions: dense semantic embeddings are not the lever on this problem.

06 — what we are not claimingLimits, stated plainly

  • 131 examples. A consistent +0.071 across five seeds is reportable; it is not a large study. Fold-to-fold variation within a seed runs 0.10–0.18.
  • Re-seeding does not add data. It varies the split and the starting weights, so it bounds one kind of noise, not sampling error. The true uncertainty is wider than the seed spread suggests.
  • The final held-out set has not been touched — and, awkwardly, we now know it cannot settle this. That 69-pair set was recently shown to rank strong models no better than chance. It reliably identifies broken models and nothing else.
  • There is no clean way to score this yet. The larger 200-pair population is the right one, but this model trains on 131 of those 200. Closing that gap needs more real labelled outcomes, not a better architecture.
  • No latency measurement exists. Nothing here has been timed against the 100 ms budget the product actually has.
If you read one caveat

This is a cross-validated result on 131 outcomes, not a verified win. What makes it worth reporting is that it held in every seed and that the effect has a plain mechanical explanation. What would make it real is more labelled data — which is the actual bottleneck, and has been for a while.

07 — what we would do next

  • Strip it back further. If a plain average matches learned attention, test whether the three similarity numbers alone match the whole 32-dimensional interaction block. The simple version keeps winning; find its floor. Free to run.
  • Keep the per-ask verdicts regardless of accuracy. They let the product say "we introduced Garrett because you asked for brand-side operations leaders." Nothing else we have built can produce that sentence.
  • Stop buying embeddings. Two independent measurements now say dense semantics do not move this problem. Spend on labelled outcomes instead.
