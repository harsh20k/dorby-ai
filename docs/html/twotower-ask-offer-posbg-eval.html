Eval-time offer trim does not fix ask/offer

Same trained ask_offer_001 adapters, rescored on all 200 real pairs with offer text set to positioning + background only — the fields the design specified. No retraining. No holdout split.

Combined pair AUC 0.557 — down from 0.571

What was tested

  • Isolated package twotower_ask_offer_posbg_eval/ — does not edit twotower_ask_offer/.
  • Ask tower still sees lookingFor + seeker searchQuery.
  • Offer tower now sees only positioning + background at eval. It was trained on every field except lookingFor.
  • λ = 1.75, the training value, not refit. Population: 200 real pairs (100/100), 178 candidates.

This is not the intended experiment. The offer tower still learned on notes, location, and prefs. Feeding it only positioning + background at eval time drops combined AUC. A correct test needs a new training run.

How to read this

  • The reciprocal term still helps vs forward-only (0.521 → 0.557), just less than with the wider offer text.
  • You cannot patch a field-split bug after training by swapping the eval strings.
  • Original docs said offer = positioning + background; the training code used every field except lookingFor.

Reproduce

python -m pytest tests/test_twotower_ask_offer_posbg_eval.py -q modal run twotower_ask_offer_posbg_eval/modal_eval.py --run-id ask_offer_001 --lam 1.75
