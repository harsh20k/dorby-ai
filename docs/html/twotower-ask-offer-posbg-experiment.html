Corrected ask/offer retrain is a wash

New training run with the fields the design specified: Ask = lookingFor + seeker searchQuery; Offer = positioning + background only. Scored on all 200 real pairs with the same packing. Combined pair AUC 0.575 vs the original wide-offer 0.571.

All-200 combined AUC 0.575 — a wash vs 0.571

What was tested

  • Isolated package twotower_ask_offer_posbg/ — does not edit twotower_ask_offer/.
  • Same 3008 frozen rows as ask_offer_001 / voyage_gemini_ctrl_001. Same LoRA recipe. λ = 1.75, fixed, not learned.
  • Best checkpoint: epoch 2 (dev R@1 0.352). Original wide-offer run peaked at epoch 3 (0.369).
  • Headline population: 200 real pairs (100/100), 178 candidates. Holdout is reported below but is not the ranking that matters among strong models.

Matching train and eval fields recovers the original combined AUC. Narrowing offer to positioning + background at training time does not help, and does not hurt much either. The earlier 0.557 drop was the train/eval mismatch, not the field set.

How to read this

  • The reciprocal term still helps vs forward-only (0.516 → 0.575, +0.059) — same size lift as the original wide-offer run (+0.059).
  • Forward-only is still near chance. Two narrow towers still do not beat frozen Voyage-4-nano’s own forward score (0.564).
  • Retrieval is a hair worse (R@1 0.24 vs 0.27). Hard-neg ticks up (0.544 vs 0.524); easy-neg drops (0.651 vs 0.695).
  • Does not beat voyage_gemini_ctrl combined all-200 (0.659). One shared full-profile tower plus a free post-hoc reciprocal sweep remains stronger.
  • Holdout combined 0.598 / forward 0.585 / R@1 0.345 — do not rank models on the 69-pair split.
