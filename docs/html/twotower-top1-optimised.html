Chasing recall@1: one change failed, one won quietly

Sharpening the loss to focus on the top competitor backfired on every metric. Fixing which checkpoint we ship produced the best model in the project — and the small holdout hid it completely.

The problem

Getting the right person into the shortlist works. Getting them to first place never has. Across the whole project, the best top-1 result belonged to a model that was never trained at all — frozen voyage-4-nano, 18 correct out of 100. Fine-tuning it moved that number by exactly zero, while clearly improving everything else: the right person went from an average position of 18th to 12th.

So the model learned to pull the target up the list, but not to close the last step. This experiment changed two things to attack that step directly, accepting up front that other metrics might suffer.

Arm A (previous best) standard loss · ship the checkpoint that wins a 2-candidate test
Selection fix standard loss · ship the checkpoint that ranks best against a real pool
Sharpened loss concentrate learning on the single hardest competitor · same selection fix

Everything else identical — same training data, same batch size, same number of weight updates, same learning rate. Each rung adds one change.

The quiet win

Simply changing which trained checkpoint we ship — with no change to how the model learns — produced the best MRR of any model in this project, ahead of the production model and of a model 23× larger. It is also the first fine-tuned model to beat the untrained baseline at top-1: 19 correct out of 100 versus 18.

That last gap is one query, which is exactly the smallest change measurable here, so it is not a significant result on its own. What makes it worth something is that the improvement in overall ranking quality is consistent in direction across all three separate groups of pairs.

The failure

Sharpening the loss lost on every metric, including the one it was designed to improve. Top-1 fell from 18 to 14 of 100 — below the untrained model — and its ability to tell apart genuinely difficult pairs dropped to worse than a coin flip.

The likely reason is a bad interaction: concentrating learning on the single hardest example only helps if that example is correctly labelled. Our training labels come from a language model that is right about 59% of the time on exactly those hard cases. Sharpening worked as designed — it sharpened onto the noise.

The small test set hid the win — for the third time

On the 69-pair holdout that every earlier number in this project used, the selection fix looks like nothing happened: identical top-1, a rounding-error change elsewhere. Only on the full 200 pairs does it show up as the best model measured.

Stated plainly

I first wrote this arm off as a non-result based on the small test set alone. That was wrong, and it is the third time that same test set has produced a misleading conclusion in this project. The working rule now: no result counts until it has been measured on all 200 pairs.

A side benefit that matters more than the numbers

Until now, the signal used to pick which trained checkpoint to keep measured a completely different task from the one we actually care about — it asked "does the right answer beat these one or two wrong answers?" rather than "does it come first out of many?".

That mattered: in both earlier experiments this signal preferred the worse model, and was wrong both times. With the fix, it correctly ranked the two arms here — it preferred the control (0.3333) over the sharpened arm (0.3000), and the real results agreed. For the first time this project has a development signal that points the right way, which is a precondition for tuning anything else.

One limit: the development pool is 86 candidates, so its recall@10 already saturates at a perfect score and carries no information. Only its top-1 and overall-ranking numbers are usable at this size.

What this leaves

  • Mine the competitors that actually beat us. Untouched, and this result strengthens the case: the problem is not that the model ignores hard competitors, it is that the hard competitors it trains against were chosen once, by a different model, from a synthetic pool.
  • Show the model far more competitors per step. This experiment suggests why concentration cannot substitute for volume — focusing harder on few noisy examples amplifies the noise.
  • Improve the training labels. 59% accuracy on hard cases is a hard ceiling on anything trying to learn fine distinctions at the very top of a ranking.

One run per arm, so there is no repeat-run error estimate here. Top-1 on 100 queries moves in steps of one query, so the +1 result sits exactly at the resolution limit; the sharpened arm's −4 does not. Training labels are a language model's opinion on synthetic profiles — only the evaluation uses real outcomes.
