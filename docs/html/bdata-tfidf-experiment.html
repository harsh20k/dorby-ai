Keyword overlap does not predict accept vs decline on B-data

First isolated experiment on the locked production dump data/B-data.json: unsupervised TF-IDF cosine between seeker (query + profile) and candidate profile, scored on ACCEPT vs REJECT only.

Holdout pair AUC 0.512 — near chance

What B-data is

Not the original 200 labeled pairs. Each row is one seeker + one search query + a short list of matched candidates. The human outcome sits on each match as status (ACCEPT / REJECT / PENDING). Candidates have no contact ids.

Simple things you can already see

  • Most intros are still open. About two-thirds of matches are PENDING. Over half of seekers never got a yes/no in this dump.
  • When people decide, they usually say yes. Among resolved matches, accepts beat rejects about 6:1.
  • Channel matters. SMS intros get decided much more often (~69% resolved) than background matches (~22%). SMS is also more yes-heavy when decided.
  • Candidates reuse without ids. Matching profile text shows ~26.7k unique candidate profiles across 58k slots — many people are offered repeatedly. Some seeker profiles also appear as candidates elsewhere.
  • Easy surface features barely predict the outcome. Query length and how filled-out a profile is look almost the same for ACCEPT, REJECT, and PENDING.

The TF-IDF experiment

Isolated package bdata_tfidf/. Drop PENDING. Score ACCEPT vs REJECT with TF-IDF cosine (same lexical idea as the original baseline). Fit vocabulary on train texts only. Freeze a seeker-disjoint 70/30 split. Report holdout pair metrics via shared baselines/metrics.py.

Lexical similarity does not separate accept from decline here. Overall AUC is chance; within-seeker ranking is chance; hard negatives score below chance — keyword overlap marks “looks related” intros that humans still reject.

How to read this

  • B-data is large and realistic, but mostly unfinished and yes-skewed when finished.
  • It is a different population from the balanced 200-pair seed set.
  • TF-IDF fails as a first floor on this dump — not because the package is broken (train AUC also near chance), but because accept/decline here is not a keyword-overlap problem.
  • Next experiments should assume lexical cosine is a weak baseline on B-data, and treat PENDING carefully (or keep dropping it).
