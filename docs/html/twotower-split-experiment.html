Does Splitting the Two-Tower Into Separate Adapters Help?

Every fine-tune in this project so far used one shared model for both the search-query side and the candidate side. This experiment tried the real architectural idea instead: two separate LoRA adapters, one specialized for queries, one for candidates, trained jointly. It's the worst of the three approaches tested — worse pair AUC, much worse hard-negative AUC, worse MRR — likely because splitting throws away the frozen base model's already-aligned query/document space, and 583 training rows isn't enough to rebuild that alignment from two independently-initialized adapters.

All 200 real pairs

Same population, same metrics as every other row in this project. The split model trails on every metric — sharply on hard-negative AUC, which drops below chance.

Dev recall@1 per epoch. It peaked at epoch 1 and got worse every epoch after, even as training loss kept falling — the checkpoint-selection mechanism caught this and kept epoch 1's adapters.
