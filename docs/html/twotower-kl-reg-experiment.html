Does a Leash to the Frozen Model Fix Two-Tower Overfitting?

Every custom-loop two-tower run in this project — run_001, the split-tower experiment, the field-gate experiment — overfits fast: dev recall@1 peaks at epoch 1-2, then gets worse every epoch after. A KL penalty against the frozen base model (the same idea RLHF fine-tunes use to stay close to a reference policy) is the standard fix for exactly that. Added to top1_ctrl's exact recipe, it worked mechanically — dev recall@1 rose and plateaued instead of declining — but a same-day check showed top1_ctrl itself was already flat, so the collapse this was built to fix wasn't actually present here. On all 200 real pairs the leash is a small net negative on every metric.

How the leash works

No second model is loaded — the same LoRA-adapted model has its adapter switched off for one extra forward pass, giving the true frozen output to compare against.

adapted embeddings (adapter on) — loss as before (MultipleNegativesRankingLoss, scale 20)
+ 0.5 × KL(frozen distribution ‖ adapted distribution), from a second forward pass with disable_adapters() — same weights, no LoRA delta
Verified before GPU spend: at LoRA init (B matrix = 0) the two passes are numerically identical (max diff 0.0).

The leash worked — on a problem this recipe didn't have

Dev recall@1 for the KL-regularized run rises and plateaus, never declining, unlike every prior custom-loop run. But top1_ctrl's own curve (no KL, dashed) was already just as flat — the early-collapse pattern belongs to the split-tower and field-gate architectures, not to this single-shared-tower recipe.

What this means

Does the leash stop the early-epoch collapse?
Plausibly yes, mechanically — but untested on the architectures that actually showed it (split towers, the field-gate combiner). It was only tried on top1_ctrl, which turned out not to need it.
Does it make the project's best model better?
No. Small, consistent net negative on all 200 — the extra penalty adds drag against the main task with no collapse to prevent. top1_ctrl + eval-time query-weighting (recall@1 0.32, zero extra training) remains the strongest, cheapest lever found in this project.
