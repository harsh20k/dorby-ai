How uniqueness was defined

Candidates in B-data have no ids. Full-profile hashes overcount people whose text drifts slightly. Positioning is almost never empty, so it is the primary key.

  • If positioning is nonempty → hash that text.
  • Else hash the first nonempty of background, lookingFor, location, intro/personal/meeting prefs.
  • All-empty profiles (9 slots) are dropped.
  • Duplicates keep the richest profile text, union of seeker ids and queries.

This is inferred identity, not Boardy’s contactId. Same person with two different positioning strings counts twice; two people with identical positioning collapse to one.
