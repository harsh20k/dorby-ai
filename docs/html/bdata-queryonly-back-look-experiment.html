The 200-pair nano win does not transfer to B-data

Same LoRA, same packing: seeker = search query only, candidate = background + lookingFor. Scored on every resolved pair in locked data/B-data.json, plus retrieval against the unique-candidate pool.

Pair AUC 0.5075 — chance; 200-pair was 0.5983

What was tested

  • Isolated package bdata_queryonly_back_look/ — does not edit twotower_queryonly_back_look/, bdata_voyage_nano_posbg/, or bdata_voyage_nano/.
  • Adapter queryonly_back_look_001 on voyage-4-nano (max_length 4096, dim 1024).
  • No train/holdout split. PENDING dropped; ACCEPT vs REJECT on all 18,304 resolved pairs (15,821 / 2,483) from 6,962 seekers.
  • Retrieval: each ACCEPT query ranked against 21,168 unique match-role people (2 ACCEPT pairs skipped).
  • Local Chroma cache under this experiment’s artifacts (21,168 candidates, 15,819 queries). Metrics stay exact NumPy, not ANN.
  • Modal A10G ap-54RNu0bDrg3u8hfhlwsx85 stopped 14:44 ADT, ~35 min, clean completion.

Pair AUC 0.5075 is the transfer failure (pool-size invariant, was 0.598). The frozen control on the same 18,304 pairs and packing is 0.4869 — LoRA is a small bump, both chance. R@1 0.012 vs 0.30 is mostly the list getting 119× longer (178 → 21,168 people), not 15k queries. Same-quality dilution predicts R@1 ≈ 0.0025; we beat that (~5×). Frozen 200-pair R@1 0.28 dilutes to ≈ 0.0024; observed 0.0139 is ~6×.

Expected R@1 if the model were unchanged

The ~15k count is queries (15,819 ACCEPT), not the ranking pool. Recall@1 depends on how many people you rank against. 200-pair eval: 100 queries into 178 candidates. This run: 15,819 queries into 21,168. Pool ratio 21,168 / 178 ≈ 119×.

Absolute R@1 of 0.30 was never a fair B-data target. Observed 0.012 is better than i.i.d. dilution, likely because the 178-person seed corpus is production’s already-hard shortlist and the 21k pool is mixed. Pair AUC has no such excuse.
