Retesting a KL Leash on a Bigger Batch — It Loses Again

An earlier experiment added a KL-divergence penalty against the frozen base model (kl_reg_ctrl_001) to stop early-epoch overfitting — and it made things slightly worse. This retests the identical mechanism on voyage_gemini_ctrl_001's much bigger, leakier batch, to see if the earlier verdict was just a small-data fluke. It wasn't. The leash loses on every metric again, by a wider margin this time, and — unusually for this project — the 69-pair holdout agreed with the real verdict instead of overstating it.

Holdout and all-200 finally agree on direction

Every other custom-loop experiment in this project has seen the 69-pair holdout mislead. This time both populations point the same way — just at different magnitudes.

The all-200 population shows a larger hard-negative AUC drop than the holdout suggested (−0.1034 vs −0.0793) — the leash hurts the metric that matters most for this project's real deployment population (production's own false positives) more than the smaller sample implied.

The mechanism works — it just doesn't help this recipe

Dev recall@1 across training, both runs.

The KL term was designed to stop a sharp early-peak-then-collapse pattern seen in other architectures (split_001, field_gate_001). top1_ctrl's plain recipe — which both runs here inherit — never showed a sharp collapse to begin with, only a mild dip. There wasn't much for the leash to fix. Same leakage caveat as voyage_gemini_ctrl_001 applies: this batch is an unreviewed pilot, measurably leakier than prior sources on pre-training checks.
