nomad_drift — isolated experiment

Dialing in the query/profile blend on 1,000 synthetic profiles

A prior experiment eyeballed the best mix of "who you are" vs. "what you're asking for" from a 9-point grid checked on the same 200 real pairs it reported. This one fits that mix on a population 13× larger and entirely separate — then checks whether the answer holds up on the real pairs it never saw.

α = 1.0
Calibrated on 2,619 judge-labeled synthetic pairs (923 profiles). The query alone — no profile blended in at all — wins on pair AUC, and it is not a close call: the curve rises without turning back, all the way to the edge of the grid.

BackgroundThe knob this is calibrating

Every model in this project encodes a seeker as one string: their profile, with Search query: … appended. query_weighted/ found that splitting the two into separate vectors and blending them — normalize(α·query + (1−α)·profile) — nearly doubled recall@1 on frozen Voyage-4-nano, with α=0.6–0.7 reading best off a 9-point sweep. That grid was scored on the same 200 real pairs the finding is reported on, so 0.6 vs. 0.7 isn’t distinguishable from noise, and α was never fit on anything the report population hadn’t already seen.

nomad_drift/ fixes that by fitting α on rrf_003 — the pairing pipeline’s 1,000-profile synthetic batch, 2,619 pairs judged by an LLM — a population that shares no profiles with the 200 real pairs. Whatever α wins there is then run, unmodified, through query_weighted.eval.run_all_arms: the exact function that produced the published table, so the numbers below sit in that same table rather than a re-implementation of it.

Phase 1 · synthetic calibrationThe sweep never turns back

Two metrics, both scored without a shared retrieval corpus (so neither can inherit the circularity the original experiment flagged in its own recall numbers): pair AUC across all 2,619 pairs, and shortlist top-1 accuracy — within each query’s judged shortlist of ~5 retrieved candidates, does the highest-scoring one carry the positive label? Only counted for the 385 shortlists that contain both a positive and a negative.

rrf_003 calibration sweep — 2,619 pairs, 418 seekers, 505 candidates
alpha = 0 is pure profile, alpha = 1 is pure query
pair AUC shortlist top-1 accuracy

Pair AUC climbs from 0.5471 at pure-profile to 0.6241 at pure-query with no interior peak — every step toward the query helps, right to the edge of what the grid can test. Shortlist accuracy is noisier (each point averages 385 five-candidate rankings, a much smaller effective sample) but points the same direction, topping out near α=0.7–1.0. Pair AUC is the tie-break authority: it’s the corpus-free metric, matching how query_weighted’s own doc treats hard-negative AUC as the "clean" signal over pooled retrieval numbers.

Phase 2 · confirmed on all 200 real pairsOne number, two different answers

Folding α=1.0 into query_weighted.eval.run_all_arms’s own alpha grid and re-running it on all 200 real pairs is where this gets interesting: the calibrated alpha does not win on the same metric it was calibrated on.

All 200 real pairs — pair AUC vs. hard-negative AUC across the full alpha range
alpha = 0 is profile_only; alpha = 1 is query_only
pair AUC (all negatives) hard-negative AUC concat_baseline (current production text)
The two AUCs disagree about where the optimum is, and that disagreement is the finding. Overall pair AUC on real-200 peaks in the interior, at α=0.6 (0.5872), then falls back to 0.5530 at pure query — a little profile similarity still helps separate the easy negatives that make up most of the pool. Hard-negative AUC keeps climbing the whole way, peaking exactly where the synthetic calibration landed: α=1.0, at 0.5914 — matching query_weighted’s own published finding that this is the best hard-negative AUC of any model measured on all 200 real pairs in this project. rrf_003 calibration reproduces that answer from a completely different, much larger population, without ever seeing a real pair.

Reading this honestlyCaveats

• rrf_003’s labels are an LLM judge’s opinion (google/gemini-3.1-flash-lite, naive framing), not real accept/decline outcomes — good enough to fit one scalar hyperparameter on 13× more pairs than 200 affords, but the number that counts is still the real-200 report above, which is why this package always runs it.
• α=1.0 is the edge of the grid, not a true interior optimum — the sweep never turned back, so a value "past" pure query isn’t a meaningful thing to want, but it also means the exact peak was never bracketed.
• Shortlist top-1 accuracy is not recall@1 — it’s a within-shortlist ranking check over ~5 retrieved candidates, not a full-corpus retrieval metric like the real-200 numbers above. Don’t read the two as comparable.
• One run, no replicate, no error bar on either population.
• Retrieval on real-200 carries the same partial circularity the original query_weighted doc flagged: production selected these candidates using this same search query. Pair AUC and hard-negative AUC don’t share that problem — which is exactly why hard-negative AUC matching between the two populations is the load-bearing result here, not the recall@1 jump.
